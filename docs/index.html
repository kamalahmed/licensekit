LicenseKit Documentation

A self-hosted licensing and update server for WordPress plugins and themes. Sells via Easy Digital Downloads or WooCommerce. Includes a single-file client SDK.

What is LicenseKit?

LicenseKit turns your WordPress site into a complete licensing infrastructure for the plugins and themes you sell. It handles three things:

  1. License issuance — when a customer buys your product through EDD or WooCommerce, a unique license key is generated and emailed to them.
  2. License validation — the customer's installed plugin or theme periodically checks in with your server to confirm the license is still valid.
  3. Update delivery — when you upload a new version, the customer's WordPress sees the update through its standard "Updates" screen, exactly as if it came from wp.org.

LicenseKit is a drop-in replacement for paid extensions like EDD Software Licensing. It works for both Easy Digital Downloads and WooCommerce. It's GPL-2.0+, self-hosted, and you keep 100% control of your licensing infrastructure.

Two roles: vendor and customer

To understand how LicenseKit works, separate the two roles:

RoleWhoWhereWhat they do
Vendor You Your shop site, e.g. shop.example.com Install LicenseKit + EDD or WooCommerce, list products, upload releases. Your products' sales and license records all live here.
Customer Your buyers Their own WordPress sites Install your plugin or theme, paste their license key into a field, click Activate. Receive automatic updates from your server.
Customers never see LicenseKit's admin or settings. The server URL and the public verification key are baked into your plugin source by you before you ship it. The customer only ever interacts with a license-key input field your plugin renders.

Vendor installation

One-time setup on your shop site (e.g. shop.example.com):

  1. Install and activate WordPress 6.0 or newer, PHP 7.4 or newer.
  2. Install and activate either Easy Digital Downloads or WooCommerce (or both).
  3. Upload licensekit.zip, install and activate it from the Plugins screen.
  4. Open License Kit → Settings in the admin.
  5. Copy the Ed25519 public key at the top of the page. You'll paste this into your plugin or theme source code in a moment.
Production hardening: Move the secrets into wp-config.php for production: 
define( 'LICENSEKIT_HASH_PEPPER',     'paste-from-Settings' );
define( 'LICENSEKIT_DOWNLOAD_SECRET', 'paste-from-Settings' );
define( 'LICENSEKIT_HMAC_SECRET',     'paste-from-Settings' );
define( 'LICENSEKIT_SIGN_SECRET',     'paste-from-Settings' );
define( 'LICENSEKIT_SIGN_PUBLIC',     'paste-from-Settings' );
Keeping secrets out of the database means a leaked DB backup alone can't be used to forge license validation responses or decrypt stored keys.

Sell your first licensed product

via Easy Digital Downloads

  1. Downloads → Add New. Create a download for your plugin (e.g. "Loginless Pro").
  2. Upload your plugin's .zip as the download file in the standard EDD Download Files section.
  3. Scroll to the LicenseKit Settings meta box in the right sidebar:
    • Check Issue a license key on purchase.
    • Pick a tier (Single site, Five sites, Unlimited, or Custom).
    • Set Sites per license (e.g. 1; use 0 for unlimited).
    • Pick an expiry: 1 year, 6 months, 1 month, or Lifetime.
  4. Publish the download. Customers can now buy it through your storefront.

That's it. When a purchase completes, LicenseKit auto-creates a matching Product record (linked to the EDD download), issues a license key for the buyer, and emails it to them.

via WooCommerce

WooCommerce integration is coming in v1.1. The mechanics will mirror EDD: a "LicenseKit Settings" panel on the product editor, license issuance hooked on woocommerce_order_status_completed, and a "My Licenses" section in the WooCommerce My Account area.

Integrate the SDK in your plugin or theme

The Client SDK is a single PHP file that runs inside your customer's plugin or theme. It handles license activation, validation, the Activate/Deactivate UI, and update delivery. Three steps to integrate.

Step 1 — Copy the SDK file

Take client-sdk/licensekit-client.php from this plugin and place it inside your plugin or theme:

my-awesome-plugin/
├── my-awesome-plugin.php
├── lib/
│   └── licensekit-client.php  ← copy here
└── ...

Step 2 — Boot the SDK from your plugin's main file

Add this near the top of your plugin's bootstrap. Replace the server_url with your shop URL and the public_key with the Ed25519 public key from your LicenseKit Settings page.

<?php
defined( 'ABSPATH' ) || exit;
define( 'MYP_VERSION', '1.0.0' );

require_once __DIR__ . '/lib/licensekit-client.php';

add_action( 'plugins_loaded', static function () {
    \LicenseKit_Client_v1::boot( [
        'product_slug'       => 'my-awesome-plugin',
        'plugin_file'        => __FILE__,
        'item_type'          => 'plugin',
        'server_url'         => 'https://shop.example.com',
        'version'            => MYP_VERSION,
        'license_option_key' => 'myp_license',
        'text_domain'        => 'my-awesome-plugin',
        'render_field_hook'  => 'myp_render_license_field',
        'public_key'         => 'BASE64_ED25519_PUBLIC_KEY_FROM_SETTINGS',
    ] );
}, 5 );

Step 3 — Render the license field in your settings page

Anywhere you want the license input + Activate button to appear, do:

<?php do_action( 'myp_render_license_field' ); ?>

The hook name is whatever you passed as render_field_hook. The SDK takes care of the input, the button, the status badge, and the form-post handler.

Theme variant

For themes, swap plugin_file for stylesheet and set item_type to 'theme':

require_once get_stylesheet_directory() . '/lib/licensekit-client.php';
\LicenseKit_Client_v1::boot( [
    'product_slug'       => 'my-theme',
    'stylesheet'         => get_stylesheet(),
    'item_type'          => 'theme',
    'server_url'         => 'https://shop.example.com',
    'version'            => wp_get_theme()->get( 'Version' ),
    'license_option_key' => 'mytheme_license',
    'text_domain'        => 'my-theme',
    'render_field_hook'  => 'mytheme_render_license_field',
    'public_key'         => 'BASE64_ED25519_PUBLIC_KEY_FROM_SETTINGS',
] );

What customers experience

  1. They buy your plugin through your EDD or WooCommerce checkout.
  2. The post-checkout receipt page and email both show their license key in a "Your License Keys" table.
  3. They download the plugin zip from your shop, upload it to their WordPress, activate it.
  4. They visit your plugin's settings page and paste their key into the license field, then click Activate.
  5. Done. Updates flow through WordPress's standard Plugins → Updates screen. Changelogs appear in the "View details" popup.

If you place the [licensekit_customer_licenses] shortcode on a page (typically the EDD or WooCommerce account page), customers can see all their licenses with a click-to-copy key field, status badge, activations used / limit, expiry, and a Rotate Key button.

Self-rotate: if a customer suspects their key has been compromised or just wants a fresh one, they click "Rotate Key". The new key inherits the existing expiry (no extra validity is added) and existing activations on real sites continue working — only their cached key text on each site needs to be updated. Rate-limited to 3 rotations per license per day.

License states and lifecycle

StateValidation works?Updates available?How it gets here
activeYesYesDefault state on issuance.
expiredSometimes (in grace)NoPast expires_at. If grace_until is set and in the future, validation still works; downloads always denied.
disabledNoNoManually paused by the vendor (e.g. payment dispute).
revokedNoNoAuto-set on refund, or manually by vendor for abuse.
pendingNoNoAwaiting first payment (rare; for offline-pay flows).

Activation rows have their own simpler lifecycle: active when a site is using the license, deactivated when the site removed itself or admin revoked, revoked for explicit per-site bans. There's only ever one row per (license, site) pair — re-activating flips the existing row's status back to active and updates the activated_at timestamp.

Vendor REST API

For automating release uploads from CI/CD and integrating with your own tooling. All admin endpoints live at /wp-json/licensekit/v1/admin/* and require a Bearer token in the Authorization header.

Generating a token

Open License Kit → API Tokens in the admin, click Create Token. The full token is shown once — store it in your CI's secret manager. The token format is lk_xxxxxxxx_yyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyy; only the prefix is recoverable later.

Webhooks

LicenseKit can call any URL you configure when license or release events happen. Set them up at License Kit → Webhooks.

Events

  • license.issued — a new license was created (purchase, manual, or renewal).
  • license.activated — a customer site activated a license.
  • license.deactivated — a customer site deactivated.
  • license.rotated — license key was rotated (admin or self-service).
  • license.extended — expiry extended (renewal or admin).
  • license.status_changed — status flipped between active/expired/disabled/revoked.
  • license.suspicious_activity — too many failed activations on one key.
  • release.created — a new release was uploaded.
  • release.deleted — a release was deleted.
  • release.downloaded — a customer downloaded a release zip.

Delivery format

POST request, JSON body, with these headers:

Content-Type: application/json
X-LicenseKit-Event:     license.issued
X-LicenseKit-Delivery:  <numeric delivery id>
X-LicenseKit-Signature: sha256=<hex>

Verify the signature on your end:

$expected = 'sha256=' . hash_hmac( 'sha256', $raw_body, $webhook_secret );
$signature = $_SERVER['HTTP_X_LICENSEKIT_SIGNATURE'] ?? '';
if ( ! hash_equals( $expected, $signature ) ) {
    http_response_code( 403 );
    exit;
}

If your endpoint returns 2xx the delivery succeeds. Non-2xx responses trigger exponential-backoff retries: 1m → 5m → 15m → 1h → 2h, then give up after 5 attempts.

Security model

ConcernHow LicenseKit handles it
Update tampering / supply chain Every server response is signed with Ed25519. The vendor's private key stays on the server; the SDK ships with the matching public key. An attacker reading the plugin source gets only the public key, which can verify but cannot forge.
Plugin zip integrity Releases are stored under uploads/licensekit/releases/ with a .htaccess deny-all + web.config deny-all. Downloads go through a PHP endpoint with a 5-minute, single-use, HMAC-signed token. Direct URL access to the zip is blocked.
License-key brute force Per-IP rate limit (30/min on license endpoints), per-key rate limit (10/min on activate). After 5 failed activations on the same key within 15 minutes, the key is locked out for 15 minutes and a license.suspicious_activity webhook fires.
HTTPS Public REST endpoints reject non-HTTPS requests unless LICENSEKIT_ALLOW_HTTP is defined (development only). The Client SDK refuses non-HTTPS server URLs unless dev_mode is on.
License key at rest Stored as a peppered SHA-256 hash for lookup, plus a sodium-encrypted copy for the customer dashboard "reveal" feature. The encryption key derives from the pepper, so a leaked database alone (without wp-config.php) cannot recover keys.
GDPR Standard WordPress privacy tools: Tools → Export Personal Data and Erase Personal Data include all LicenseKit licenses and activations matching the customer's email.

Production checklist

  1. HTTPS everywhere: shop URL, customer URLs, all webhook URLs.
  2. Move all five secrets to wp-config.php (see Vendor installation above).
  3. Set Settings → Delete data on uninstall according to your operator policy.
  4. Configure Settings → Grace period (default 14 days; set 0 to disable).
  5. Test the full purchase loop in EDD/WC test mode before going live.
  6. Subscribe at least one webhook to license.suspicious_activity so you get alerted to brute force.
  7. For each plugin/theme you ship: confirm that dev_mode is not set when you build the production zip.
  8. Document a customer-support flow: "I lost my license key" → direct them to the [licensekit_customer_licenses] shortcoded page on your site.

Extension filters

LicenseKit exposes a small set of filters and actions for vendors who want to customize behavior without forking the plugin. Apply them from your theme's functions.php or a small "must-use" plugin in wp-content/mu-plugins/.

Customizing tier and expiry labels

The default tier dropdown ships with technical labels (Single site / Five sites / Unlimited / Custom). Replace them with whatever marketing labels match your offering — Personal / Studio / Agency, Indie / Pro / Enterprise, etc. The label is purely cosmetic; the actual enforcement uses activation_limit.

add_filter( 'licensekit_tier_options', function ( $tiers ) {
    return [
        'personal' => __( 'Personal — 1 site' ),
        'studio'   => __( 'Studio — 5 sites' ),
        'agency'   => __( 'Agency — 25 sites' ),
        'unlimited' => __( 'Unlimited' ),
    ];
} );

add_filter( 'licensekit_expiry_options', function ( $periods ) {
    return [
        '3m'       => __( '3 months' ),
        '1y'       => __( '1 year' ),
        '2y'       => __( '2 years' ),
        'lifetime' => __( 'Lifetime' ),
    ];
} );
Set tier and activation_limit consistently. If you choose tier='agency' in the dropdown but leave activation_limit=1, customers will see "Agency" but only get one activation. Pick a tier value and put the matching limit in the field below it.

Adjusting the grace period

By default, an expired license remains usable for 14 days after expiry (downloads are still denied during grace; only validation succeeds). Change this with:

add_filter( 'licensekit_grace_period_days', function () {
    return 30; // give customers a 30-day grace window
} );

Tweaking log retention

Audit logs are pruned daily; default 90 days. Raise or lower:

add_filter( 'licensekit_log_retention_days', function () {
    return 365;
} );

Programmatic license-active override

Useful for emergency overrides or test rigs. Returning true here treats the license as active for a single page load even if the server says otherwise:

add_filter( 'loginless_pro_license_active', function ( $active, $key ) {
    if ( defined( 'WP_CLI' ) && WP_CLI ) {
        return true; // Always active in WP-CLI context
    }
    return $active;
}, 10, 2 );

Domain customization (SDK side)

From your plugin source, override the LicenseKit server URL or public key with filters so site operators can swap them in wp-config.php without editing your shipped code:

// In your plugin's main file, replacing the hardcoded values
add_filter( 'loginless_pro_licensekit_server', function ( $url ) {
    return defined( 'MY_LICENSE_SERVER' ) ? MY_LICENSE_SERVER : $url;
} );

Troubleshooting

Customer says "License key not recognized"

Check License Kit → Logs. If you see license.activate attempts with error: invalid_key, the key the customer typed doesn't match anything in your DB. Common causes: typo, key was rotated and they're using the old one, or they bought from a different vendor's shop. The license-prefix search in the Licenses page can help confirm the key exists.

Customer's plugin doesn't see updates

From the customer's site: WordPress dashboard → Tools → Site Health → Info → WordPress Constants. Confirm WP_DEBUG is off (otherwise the SDK runs in dev mode). On their Plugins → Updates screen, click Check again to force-refresh transients. If still nothing, increase your release version and verify the current_version on the LicenseKit Product reflects the new release.

Receipt email doesn't show the license key

LicenseKit auto-appends a "Your License Keys" block to the EDD/WC purchase receipt email body. If it's missing, check that you (a) marked the order as completed (LicenseKit only fires on edd_complete_purchase / woocommerce_order_status_completed), and (b) the product had "Issue a license key on purchase" enabled before the order was placed.

Activations limit reached unexpectedly

Local environments (localhost, *.local, *.test, RFC1918 IP ranges) are exempt from activation limits by default. Staging environments where the customer's WP_ENVIRONMENT_TYPE is 'staging' are also exempt. If a real site is being mis-detected, customers can set WP_ENVIRONMENT_TYPE to 'staging' in their wp-config.php.

FAQ

Does LicenseKit work without WooCommerce or EDD?

Yes — you can issue licenses manually from the admin, or via the REST API. The e-commerce bridges only automate issuance on purchase; nothing else depends on them.

Can I migrate from EDD Software Licensing?

v1 doesn't include a migration importer. It's planned for v1.1.

What happens when a customer's license expires?

If you've configured a grace period (default 14 days), validation still succeeds during grace — their plugin keeps working. Downloads are denied during grace, so they can't get new updates without renewing. After grace expires, validation fails and the SDK simply stops injecting updates; the host plugin's other functionality is never disabled.

Can I let a customer use the same license on a staging site without it counting?

Yes — the SDK auto-detects local and staging environments and reports them to the server, which exempts them from activation limits.

What if I lose my Ed25519 private key?

The private key is auto-generated on plugin activation and stored in either wp-config.php or wp_options. If you lose both (e.g. catastrophic server failure with no backup), open Settings → Rotate Secrets on a fresh install. This generates a new keypair. You then need to ship updated plugins to your customers with the new public key — old plugins won't be able to verify responses signed by the new private key.

Is there a CDN / S3 option for release downloads?

Not in v1 — releases stream from PHP. For high-volume scenarios, you can put a CDN in front of the entire WordPress site; the signed-token URL is unique per request so caching is fine.
